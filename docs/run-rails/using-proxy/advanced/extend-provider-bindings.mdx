Use this walkthrough when your gateway adds a field to an otherwise supported
Chat Completions response. You will allow a root-level `gateway_trace_id` while
keeping the existing assistant text checks and rejection of other unknown fields.

First confirm that the field is diagnostic metadata, rather than generated
content your checks should inspect. This example treats its value as opaque:
the proxy preserves it without inspecting its contents. It extends buffered
responses only; streaming continues to use the existing Chat event binding.
New content channels need corresponding extraction and checking support.

This walkthrough requires a gateway that actually returns the custom field.
`https://gateway.example/v1` marks that deployment-specific URL; replace it
with your gateway's API base and use its model ID and credentials. Ordinary
OpenAI does not return `gateway_trace_id`. The verification tests later on this
page supply controlled responses and need no gateway or provider calls.

## Declare and bind the field

Use the active library environment from the [quickstart](/run-guardrailed-inference/using-proxy/quickstart). Save this
as `gateway_binding.py` in the repository root:

```python
from dataclasses import replace
from typing import ClassVar

from nemoguardrails.server.experimental.provider.projection_policy import (
    ObjectPolicy,
    payload_contract,
    text_location,
)
from nemoguardrails.server.experimental.providers.openai.chat_completions.endpoint import CHAT_COMPLETIONS_ENDPOINT
from nemoguardrails.server.experimental.providers.openai.chat_completions.response_projection import (
    ChatCompletionsGuardedResponseProjection,
)


class GatewayResponseProjection(ChatCompletionsGuardedResponseProjection):
    policy: ClassVar[ObjectPolicy] = replace(
        ChatCompletionsGuardedResponseProjection.policy,
        opaque=(*ChatCompletionsGuardedResponseProjection.policy.opaque, "gateway_trace_id"),
    )


class GatewayGuardedResponse(GatewayResponseProjection):
    guarded_text_location = text_location(GatewayResponseProjection)
    projection_contract = payload_contract(
        GatewayResponseProjection,
        projection_id="example.gateway.chat_completions.response.text.v1",
        direction="response",
    )


GATEWAY_ENDPOINT = replace(
    CHAT_COMPLETIONS_ENDPOINT,
    contract_name="example_gateway_chat_completions",
    guarded_response_model=GatewayGuardedResponse,
)
```

The projection adds one allowed name. Rebuilding the payload contract and text
location binds that policy to runtime extraction. The endpoint retains the
existing request policy, route, error handling, and stream hooks.

## Select the extended endpoint

After copying `proxy-example` as described in the quickstart, create
`gateway_app.py` in the repository root:

```python
from dataclasses import replace
from pathlib import Path

from nemoguardrails.server.experimental.application import ConfigEntry, create_proxy_application
from nemoguardrails.server.experimental.providers.openai.integration import create_openai_chat_integration

from gateway_binding import GATEWAY_ENDPOINT

integration = replace(
    create_openai_chat_integration(base_url="https://gateway.example/v1"),
    endpoints=(GATEWAY_ENDPOINT,),
)
app = create_proxy_application(
    providers=(integration,),
    rails_configs=(ConfigEntry("standard", Path("proxy-example/rails")),),
)
```

Replace the upstream URL, then run from the repository root:

```bash
uvicorn gateway_app:app --host 127.0.0.1 --port 8000
```

This selects the custom endpoint through direct Python composition. The YAML
launcher's native and LiteLLM bindings remain unchanged. Use the
[quickstart request](/run-guardrailed-inference/using-proxy/quickstart#send-a-buffered-request) to exercise your
gateway with its model ID and authorization header. The proxy needs no gateway
SDK; any configured detector services retain their own dependencies and keys.

## Verify the boundary

The test commands below use the repository's development dependencies and
network-blocking test fixtures. Run them from a source checkout; the application
and exporter above also work with an installed library build.

Save this as `test_gateway_binding.py` beside `gateway_binding.py`:

```python
from copy import deepcopy

import pytest
from pydantic import ValidationError

from nemoguardrails.server.experimental.provider.contract_export import export_guard_contract
from nemoguardrails.server.experimental.providers.openai.chat_completions.endpoint import CHAT_COMPLETIONS_ENDPOINT

from gateway_binding import GATEWAY_ENDPOINT, GatewayGuardedResponse


def test_gateway_metadata_boundary():
    payload = {
        "choices": [{"message": {"role": "assistant", "content": "Hello!"}}],
        "gateway_trace_id": "trace-123",
    }
    GatewayGuardedResponse.model_validate(payload)
    with pytest.raises(ValidationError):
        CHAT_COMPLETIONS_ENDPOINT.guarded_response_model.model_validate(payload)
    with pytest.raises(ValidationError):
        GatewayGuardedResponse.model_validate({**payload, "another_field": "extra"})
    unsupported = deepcopy(payload)
    unsupported["choices"][0]["message"]["reasoning_content"] = "extra generated text"
    with pytest.raises(ValidationError):
        GatewayGuardedResponse.model_validate(unsupported)
    contract = export_guard_contract(GATEWAY_ENDPOINT)
    field = contract["response"]["properties"]["gateway_trace_id"]
    assert field["x-nemo-guardrails"]["classification"] == "opaque"
```

Run the test from the repository root:

```bash
make test TEST=test_gateway_binding.py WORKERS=0 ARGS="-q --block-network"
```

This checks the declared acceptance boundary and export. The next test exercises
the endpoint through the application with real local Rails checks.

## Verify forwarding and blocking together

Save this as `test_gateway_exchange.py` beside `gateway_binding.py`. It creates
its own local regex Rails configuration and uses an in-process upstream, so no
provider credentials or network service are needed. The test covers the buffered
response extension; the streaming binding is unchanged.

```python
import json
from dataclasses import replace

import httpx
import pytest

from nemoguardrails.server.experimental.application import ConfigEntry, create_proxy_application
from nemoguardrails.server.experimental.providers.openai.integration import create_openai_chat_integration

from gateway_binding import GATEWAY_ENDPOINT


@pytest.mark.asyncio
@pytest.mark.parametrize("text,blocked", [("Hello!", False), ("Contact person@example.com", True)])
async def test_gateway_exchange_preserves_bytes_or_blocks(tmp_path, text, blocked):
    (tmp_path / "config.yml").write_text(
        "models: []\nrails:\n  config:\n    regex_detection:\n"
        "      output:\n        patterns: ['person@example.com']\n"
        "  output:\n    flows: [regex check output]\n",
        encoding="utf-8",
    )
    upstream_body = json.dumps(
        {
            "choices": [{"message": {"role": "assistant", "content": text}}],
            "gateway_trace_id": "person@example.com",
        },
        indent=2,
    ).encode()
    received = []

    def upstream(request):
        received.append(request.content)
        return httpx.Response(
            200,
            headers={"content-type": "application/json"},
            stream=httpx.ByteStream(upstream_body),
            request=request,
        )

    integration = replace(
        create_openai_chat_integration(base_url="https://gateway.example/v1"),
        endpoints=(GATEWAY_ENDPOINT,),
    )
    app = create_proxy_application(
        providers=(integration,),
        rails_configs=(ConfigEntry("test", tmp_path),),
        http_transport_factory=lambda: httpx.MockTransport(upstream),
    )
    request_body = b'{ "model": "test", "messages": [{"role": "user", "content": "Hello!"}] }'
    async with app.router.lifespan_context(app):
        async with httpx.AsyncClient(transport=httpx.ASGITransport(app=app), base_url="http://proxy") as client:
            response = await client.post(
                "/v1/chat/completions",
                content=request_body,
                headers={"content-type": "application/json"},
            )
    assert received == [request_body]
    if blocked:
        assert response.status_code == 400
        assert response.json()["error"]["code"] == "content_blocked"
        assert text.encode() not in response.content
        assert "choices" not in response.json()
    else:
        assert response.status_code == 200
        assert response.content == upstream_body
```

Run both tests from the repository root:

```bash
make test TEST="test_gateway_binding.py test_gateway_exchange.py" WORKERS=0 ARGS="-q --block-network"
```

The allowed case asserts exact request and response bytes, including JSON
whitespace. The metadata deliberately contains the detector's matching text:
acceptance demonstrates that the field remains opaque. The blocked case puts
the same text in the assistant content and verifies that the answer is withheld.
These in-process tests establish the binding and checking behavior; exercise your
actual gateway separately to verify its wire format and network behavior.

## Export and check the contract

Generate the contract from the endpoint you bound:

```bash
python -m nemoguardrails.server.experimental.provider.contract_export \
  gateway_binding:GATEWAY_ENDPOINT --output gateway.guard.yaml
python -m nemoguardrails.server.experimental.provider.contract_export \
  gateway_binding:GATEWAY_ENDPOINT --check gateway.guard.yaml
```

The exported response includes `gateway_trace_id` as opaque; its guarded text
location and stream policy retain their existing scope. Regenerate this artifact
when you change the Python declaration. See [guard contracts](/run-guardrailed-inference/using-proxy/guard-contracts)
for how to review it and the [Chat reference](https://github.com/NVIDIA-NeMo/Guardrails/blob/develop/nemoguardrails/server/experimental/providers/openai/chat_completions/README.md)
for nested projections and stream extensions.
